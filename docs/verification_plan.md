# Verification and evaluation plan

All model accuracy, latency and user outcomes below are planned. Actual completed checks are limited to source verification, descriptive public data profiling, document rendering and local UX mockup checks. No trained model or user study has been run.

## Research questions and baselines

RQ1: How accurately can the system transcribe Russian, Kazakh and mixed sales speech under recorded call conditions? Compare a selected local Whisper configuration with a smaller or faster local configuration and, only if data transfer is approved, one managed ASR service. Record exact model revision, runtime, hardware, audio properties, language strategy, decoding and alignment configuration.

RQ2: Can evidence based extraction identify actionable objections and next actions? Compare deterministic keyword and rule extraction against a schema constrained model pipeline. Evaluate on gold transcripts and ASR transcripts from the same held out calls to isolate error propagation. Speaker identity is manually confirmed; optional diarization is evaluated separately.

RQ3: Does adding conversation information improve an outcome model beyond structured sales features? Primary MVP output is descriptive analytics. An exploratory predictive extension is allowed only with legitimate linked outcomes and adequate data. Compare constant majority baseline, structured only logistic regression, and structured plus conversation features with the same split. No positive effect is assumed. Accuracy alone is unsuitable for the imbalanced public dataset.

RQ4: Does the workflow reduce reporting effort and remain usable? Compare existing manual review with the prototype on matched tasks, counterbalance task order, record elapsed time errors corrections and user comments. A small pilot supports feasibility observations, not a population wide productivity or revenue claim.

## Sampling and annotation

Proposed feasibility corpus: 60 authorized calls, 20 primarily Russian, 20 primarily Kazakh and 20 mixed; 2 to 15 minutes per call, ideally at least 4 representatives and several products. Record noise overlap channel sample rate length and source. This is a feasibility target, not a representative sample or statistical power claim. If actual access is smaller report achieved counts and narrow conclusions.

Treat 30 development, 10 validation and 20 test calls as target counts, not a guaranteed allocation. Before splitting, build connected groups of calls that share a customer or any known speaker; the same representative can connect several customers. Assign whole groups to partitions, then report achieved call, language, customer and speaker counts. Never split an audio file into training and test excerpts. Group integrity takes precedence over exact counts and language balance. With only four representatives, the desired three-way split or language coverage may be infeasible. Obtain additional independent groups or declare a narrower evaluation; do not label a customer-only split with repeated representatives as speaker-independent. Unknown speaker identity prevents a verified unseen-speaker claim. Freeze the manifest, group identifiers, hashes and scoring rules before tuning.

A separate linked sales prediction study needs an adequately sized time-ordered cohort; 60 calls do not justify a reliable conversion model. Use an earlier training period and later test period, retain customer grouping and use only features available at a declared prediction time. Fit preprocessing, feature selection, prompts and thresholds using development/validation data only. Public telemarketing outcomes cannot be joined to unrelated speech recordings.

Two annotators independently transcribe and label the held-out material. Define rules for fillers, numbers, abbreviations, product names, code switching, incomplete words, overlap, silence and redaction. Preserve language tags. Annotate all applicable objection categories (price, timing, fit, competitor, no need or other), next action, owner and due date only if explicit, with source evidence. Record agreement before adjudication. Because objections are multilabel, calculate six separate binary Cohen kappa values with each label's counts, rather than one mutually exclusive-category kappa; flag kappa as undefined only when 1 - p_e = 0, where p_e is chance-expected agreement (for example, both annotators assigning the same constant label); retain the observed label counts. Report action-event matching F1 and normalized owner/date agreement separately, with span agreement for source evidence. Retain rare-class counts and disagreements. A generic sentiment score is not a purchase-intention label.

## Metrics and measurement conditions

WER is (substitutions + deletions + insertions) / reference words. Publish normalization rules and both raw and normalized values; normalize case, punctuation and agreed number forms consistently without deleting difficult sales entities. Language-level micro WER sums error counts and reference words before division; it is not the mean of call WERs. Report per-call distributions separately. A failed transcription of nonempty reference speech is scored as an empty hypothesis, while its processing failure is also counted. For an empty reference, per-call WER is undefined: report inserted words and the duration of the silence control separately rather than silently excluding hallucinations. Report exact match for amounts, product names, dates and customer entities, with redacted identifiers. Do not use BLEU or summary fluency as a substitute for factual correctness.

Score objections and next actions separately. Objections are call-level multilabel predictions for the six predefined categories: price, timing, fit, competitor, no need and other. For each label publish TP, FP, FN, support, precision, recall and F1 = 2TP / (2TP + FP + FN). Fix all six labels and zero_division=0 for the reported macro F1; flag absent categories as unsupported rather than silently dropping them or awarding a perfect score. A category with gold examples and no predictions has zero recall and F1. Report micro F1 and negative-call false positives as additional checks. The all-category target cannot establish coverage of a category absent from the test set.

Next actions are events rather than objection labels. Before tuning, freeze a semantic matching guide using development examples and independently adjudicated gold events. Match predicted and gold events one-to-one within a call by equivalent action meaning; use source-audio time or original gold utterances to disambiguate repeated actions, not identical segment IDs across different ASR segmentations. An unmatched or duplicate prediction is FP and an unmatched gold event is FN. Report event precision, recall and F1; score explicit owner and due-date fields separately using the agreed normalization. A missing or ambiguous owner/date remains null. Score evidence correctness separately: a semantically correct action with an unrelated citation can be an event TP but is not grounded.

Evidence precision is the number of emitted items whose cited source audio or adjudicated gold utterances support every asserted field divided by all emitted items. Judge truth against the original recording or adjudicated reference, not only against an ASR transcript that may itself hallucinate. Map predicted evidence times to that source; report consistency with the ASR text as a separate diagnostic. Missing, invalid, unrelated or audio-unsupported evidence is incorrect. Unsupported claim rate uses the same denominator. Report numerators and denominators for both gold-transcript and ASR-transcript pipelines. With no emitted items, evidence precision is Not available, never 100 percent; extraction recall still exposes missed gold events. Human reviewers check source support without seeing which method produced the item. Report model drafts and human-corrected outputs separately. Zero fabricated numeric commitments is a release condition after human review against the source, not an assertion that the raw model never invents a number.

If diarization is enabled report DER, overlap treatment, collar and speaker mapping, then measure salesperson/customer role correction accuracy independently.

Performance metrics: queue wait, end to end latency, ASR real time factor (processing seconds / audio seconds), memory and peak VRAM; report warm up exclusion and median and p95 on at least 20 runs. Backend load tests use the NFR04 fixture and reference host. Include failure and retry behavior. For a cloud alternative report billed audio minutes and any minimum rounding under its current pricing, without extrapolating local cost estimates as vendor quotes.

For uncertainty, resample independent connected customer/speaker groups with replacement and keep paired method outputs together; individual calls within a group are not independent bootstrap units. Recompute corpus-level ratios for each resample. Report the number of independent test groups, exact call and class counts, resampling seed and 95 percent interval method. With only one or two independent groups, report descriptive per-group results and explicitly withhold a generalization interval. Do not interpret overlapping small-sample intervals as proof of equivalence. Retain all failed calls and tuning decisions. For prediction report PR AUC as primary, ROC AUC and calibration as secondary, constant baseline prevalence and confusion counts at a threshold chosen on validation only. Prospective monitoring is needed before operational use.

## Proposed success targets and response to failure

Russian WER <=25 percent and Kazakh WER <=30 percent on held-out pilot material; mixed speech is reported separately until a defensible target is agreed. Proposed extraction targets are objection macro F1 >=0.75 and next-action event F1 >=0.75, reported separately, with draft evidence precision >=0.95. Record zero fabricated numeric commitments in the human-reviewed release sample and publish raw-model numeric errors separately. Empty output or missing language/class coverage cannot be presented as passing all targets. These are provisional engineering targets, not guarantees or observed results. Failure leads to correction support, a narrower supported corpus or a revised model after documented review, not selective removal of hard calls.

The fixed application tasks are import a supplied 20-row CSV and link manifest up to queued status, review one preprocessed 2-minute call and correct a planted objection, then filter the dashboard and explain its win rate. Prepare and freeze two equivalent fixture sets A/B with the same task complexity. The manual condition uses a spreadsheet for the CSV and links, plus a text editor with the preprocessed transcript and source timestamps. Both conditions must produce correct deal/call links, a corrected objection with supporting source time and a correct win-rate explanation. Queue submission belongs only to the application task: report that step separately and compare manual/application time on the common outputs, without inventing a manual queued state.

Freeze four crossover sequences: manual A then application B; application A then manual B; manual B then application A; application B then manual A. Assign one participant to each sequence and repeat the first sequence for participant five, reporting the resulting 3/2 imbalance. Give the same neutral training before timing. Start at the first task instruction and stop after the final correct explanation; count errors and assistance. Exclude ASR waiting from the 10-minute application total and report it separately. At least 4 of 5 representative users should complete the application sequence without help within 10 minutes. Compare paired times for common outputs descriptively and disclose the small convenience sample.

This full workflow study belongs to later integrated implementation. The current HTML mockup cannot read a user-supplied CSV, enqueue a real job or enforce authentication, so its synthetic sample-import walkthrough cannot pass FR02, FR04, FR01 or the complete NFR07 study. Current checks cover fixture interactions, arithmetic, evidence navigation, review state, errors, keyboard use and layout only. No representative-user test is claimed as completed.
